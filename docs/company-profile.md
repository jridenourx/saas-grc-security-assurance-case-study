# Northstar Cloud Solutions — Company Profile

## 1. Company Overview

**Company Name:** Northstar Cloud Solutions

**Business Model:** Business-to-business software as a service (SaaS)

**Industry:** Business software

**Hosting Environment:** Amazon Web Services (AWS)

**Organization Type:** Fictional small-to-medium-sized SaaS provider

Northstar Cloud Solutions provides a subscription-based software platform to business customers. Its service stores customer business records and account information and generates application activity logs to support service operations and troubleshooting.

All company information in this profile is fictional and exists solely for this case study.

## 2. Business Objectives

Northstar aims to:

* Maintain the confidentiality and integrity of customer information.
* Operate a reliable cloud-hosted service.
* Establish a repeatable security and compliance program.
* Respond consistently to customer security reviews.
* Evaluate the security risks of external service providers.
* Improve evidence collection and remediation tracking.
* Prepare for a potential SOC 2 examination.

## 3. Data Categories

For this exercise, Northstar handles the following categories of information:

| Data Category                | Description                                                    | Initial Considerations                                                          |
| ---------------------------- | -------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| Customer business records    | Information entered or maintained by customers in the platform | Access restrictions, confidentiality, retention, and integrity                  |
| Customer account information | Account identifiers and business contact information           | Access control, appropriate use, and protection against unauthorized disclosure |
| Application activity logs    | Events generated by users and application components           | Logging coverage, retention, access restrictions, and monitoring                |
| Internal operational records | Records used to administer and support the service             | Appropriate access, retention, and protection                                   |

These categories are scenario assumptions. Detailed data flows and classification rules will be established in the system description and assessment scope.

## 4. Technology Environment

Northstar operates a cloud-hosted SaaS platform using AWS services.

For this case study, technical assessments will focus on:

* Identity and access management.
* Least-privilege permissions.
* Multifactor authentication.
* Cloud activity logging.
* Logging coverage and retention.
* Relevant evidence supporting control operation.

The scenario does not assume that a production AWS environment exists. Synthetic configuration records may be used, with a sandbox environment considered only where it adds meaningful value.

## 5. External Service Providers

Northstar relies on several fictional external service providers:

| Vendor                  | Service                                   | Primary Risk Considerations                                                  |
| ----------------------- | ----------------------------------------- | ---------------------------------------------------------------------------- |
| Northstar Cloud Hosting | Cloud infrastructure and related services | Infrastructure dependency, privileged access, logging, and availability      |
| SignalBridge Support    | Customer support platform                 | Customer data access, support-user permissions, retention, and subprocessors |
| MetricForge Analytics   | Product analytics service                 | Data minimization, event data, retention, and external data sharing          |

These vendor profiles establish the starting scenario. Assessment conclusions will be based on separately developed synthetic evidence rather than assumptions that a vendor has or lacks a particular control.

## 6. Organizational Structure

Northstar has a small security and compliance function supported by other business teams.

| Function                 | Primary Responsibilities                                                                           |
| ------------------------ | -------------------------------------------------------------------------------------------------- |
| Executive Management     | Business priorities and risk acceptance within delegated authority                                 |
| Security / IT            | Security architecture, access management, technical safeguards, and security operations            |
| GRC                      | Risk assessments, control documentation, evidence coordination, findings, and compliance reporting |
| Engineering              | Application development, change management, and technical remediation                              |
| Legal / Privacy          | Contractual, privacy, and data-handling considerations                                             |
| Procurement              | Vendor onboarding and commercial relationship coordination                                         |
| Customer Success / Sales | Customer security requests and coordination with prospective customers                             |
| Business Owners          | Business justification, vendor oversight, and action ownership                                     |

These responsibilities are proposed for the simulated organization. The project will identify the appropriate owner for each relevant control and remediation action.

## 7. Current Security and Compliance Maturity

Northstar's security program is developing.

For the purposes of the case study, the initial scenario includes the following challenges:

* Vendor assessments are not performed consistently.
* Evidence supporting security claims is not always centrally tracked.
* Customer security questionnaire responses require substantial manual coordination.
* Control ownership and evidence deadlines are not consistently documented.
* Remediation activities need clearer ownership and validation requirements.
* Management needs a consolidated view of open risks and outstanding actions.

These are initial scenario assumptions. The assessments will determine which additional gaps are demonstrated by the synthetic evidence.

## 8. Intended Outcomes

The project will develop:

1. A risk-based vendor assessment process.
2. An evidence-backed customer assurance workflow.
3. A scoped SOC 2 readiness assessment.
4. Technical control validation workpapers.
5. Consolidated risk and remediation reporting.

The objective is to demonstrate how these processes can work together to support security governance and customer assurance.

## 9. Limitations

Northstar Cloud Solutions is fictional. No actual customers, vendors, employees, production systems, or company records are represented.

All subsequent assessment results must be interpreted within the defined simulation scope.
